# CircuitNET NG distribution foundation — draft

CircuitNET NG connects independent participating BBSs through an explicitly
configured ROOT/HOST/END tree. Native messages stay in each BBS's message system.
These original modern documents prepare a future distribution; they are not a ZIP
release, adopted constitution, active node list, or automatic configuration.

Proposed package contents:

- README.md, CHARTER.md, RULES.md, CONFERENCES.md, JOINING.md, SECURITY.md
- END-NODE.md, HOST-NODE.md, ROOT-NODE.md
- config/conferences.proposed.json (after review, an approved catalog)
- config/historical-dispositions.proposed.json (review rationale)
- config/network-profile.example.json (synthetic topology, no keys or endpoints)

[Charter](CHARTER.md), [rules](RULES.md), [catalog](CONFERENCES.md),
[joining](JOINING.md) and [security](SECURITY.md) are review drafts. Original modern
text follows the repository's documentation licensing. No proprietary historical
manual, Charter text, sample archive, private archaeology, credential, production
configuration or acceptance artifact belongs in the eventual package. Historical
concepts inform the drafts; no historical document is reproduced as a deliverable.

Implementation-neutral protocol participation is described in the
[transport specification](../technical/circuitnet-transport.md). SPITFIRE's
[operator manual](../manual/circuitnet.md) explains the currently implemented
services. Governance processes below are human processes, not automated software.
