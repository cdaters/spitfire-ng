# M073 — Conference-use historical intent

Retained local SFCNFUSE 1.01 documentation (July 9, 1991) was read as CP437,
without executing or modifying its executable or samples. It describes a daily
Event comparing SPITFIRE last-message-read snapshots, counting each caller once
per conference per reporting period, and producing plain BBS and optional CLR
bulletins. DOCUMENTED: its purpose was both operator conference-support decisions
and caller discovery of active conferences. Repeated browsing did not add another
unique reader that day. Offline mail-reader progress could contribute; personal
message reads that did not advance SPITFIRE's position did not. Initial execution
established a baseline rather than reconstructing prior readership. User-base
packing required reset. Hidden-conference configuration was explicit and manual.

The retained SF1STM.BBS/CLR pair contains CircuitNET caller rules, not a conference
usage report. It is relevant to access/privacy continuity, not evidence for a
health formula. No binary archaeology, executable run or source cloning occurred.

INFERRED: comparing high-water marks was a practical proxy for deliberate conference
use under the historical storage model. UNKNOWN: exact internal implementation,
edge-case snapshot recovery and behavior beyond the documentation. Modern NG uses
its own native transactional progress authority, bounded projections and access
checks; historical reports cannot establish exact per-message human reading.

Original documentation, display bytes and executables remain private research
inputs. This summary is an independently written account of behavior. See the
[modern authority and acceptance report](m074-conference-health.md).
